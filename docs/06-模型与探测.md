# 06 · 模型清单与探测新模型

[English](en/06-models.md) | 中文

`GET /v1/models` 返回的是服务端**内置白名单**（`codebuddy_direct_api.py` 里的 `KNOWN_CHAT_MODELS` / `KNOWN_IMAGE_MODELS`）。

---

## 为什么要内置白名单

上游**没有开放模型列表接口**：

```
/v2/models              → 404 Route Not Found
/v2/plugin/models       → 404 Route Not Found
/v2/model/list          → 404 Route Not Found
/v1/models              → 404 Route Not Found
```

所以列表只能人工维护。好处是：请求里的 `model` 字段是**原样透传**给上游的，
只要 id 正确，即使不在白名单里也能调用；白名单只影响 `/v1/models` 的返回内容。

## 怎么试探一个模型 id 能不能用

`model` 会原样透传，所以直接打一发就行：

```bash
KEY=$(grep '^API_KEY=' .env | cut -d= -f2-)

curl -s http://127.0.0.1:8000/v1/chat/completions \
  -H "Authorization: Bearer $KEY" -H 'Content-Type: application/json' \
  -d '{"model":"glm-5.3-flash","messages":[{"role":"user","content":"hi"}],"stream":false}' \
  | head -c 300
```

- 有正常回复 → 可用
- 返回 `{"detail":"Upstream API returned empty response"}` → 该 id 不可用

### 批量探测

```bash
# 编辑候选列表
vim tools/probe_models.py     # 改 CANDIDATES

# 跑（默认打 http://127.0.0.1:8000，可用 WB_BASE 覆盖）
python tools/probe_models.py
```

脚本用 2 并发逐个试，约 40 秒跑完 30 个候选，输出可用 / 不可用清单，
结果同时写入 `.build/probe_result.json`。

### 候选 id 从哪来

客户端（Electron 应用）的资源包里带了一份模型名册，可以直接 grep：

```bash
# macOS
grep -a -o -E '[A-Za-z0-9._-]{0,12}glm-[0-9][A-Za-z0-9._-]{0,20}' \
  "/Applications/WorkBuddy.app/Contents/Resources/app.asar" | sort -u

# Windows
grep -a -o -E '[A-Za-z0-9._-]{0,12}glm-[0-9][A-Za-z0-9._-]{0,20}' \
  "C:/path/to/WorkBuddy/resources/app.asar" | sort -u
```

> 这个名册是**所有渠道**的名字池（含 OpenRouter、Cloudflare 等第三方条目），
> 不代表 WorkBuddy 一定支持，**必须配合探测脚本实测**。

命名很容易猜错，实测过的反例：

| 看着合理但不可用 | 实际 id |
|---|---|
| `glm-5.3-fast`、`glm-5.3-highspeed`、`glm-5p3-flash`、`zai-glm-5.3-flash` | `glm-5.3-flash` |
| `glm-5`、`glm-5-turbo` | `glm-5.0` |
| `glm-4.5*`、`glm-4.6*`、`glm-4.7-flash*` | 不可用 |

## 把新模型加进白名单

编辑 `codebuddy_direct_api.py`：

```python
KNOWN_CHAT_MODELS = {
    ...
    "glm-5.3", "glm-5.3-flash",   # ← 加这里
}

# 支持 reasoning_effort 的模型要额外加进这里
THINKING_CAPABLE_MODELS = {
    ...
    "glm-5.3", "glm-5.3-flash",
}
```

然后重启服务（本机）或 `python update.py`（容器）。

---

## 免费 / 计费模型

`FREE_MODELS` 标记了不消耗 credits 的模型（`hy3-preview`、`hy4-preview`），
`/v1/models` 响应里会带 `"free": true`。

想知道某次请求实际花了多少 credits，看控制面板的请求日志 —— 那一列读的是上游返回的真实值，
不用自己估。

## 参数速查

| 参数 | 取值 | 说明 |
|---|---|---|
| `model` | 见上 | 不传则用 `DEFAULT_MODEL` |
| `reasoning_effort` | `low` / `medium` / `high` / `max` | 思考深度，也可写 `thinking_level`。仅部分模型支持 |
| `stream` | `true` / `false` | 默认 `true` |
| `temperature` | `0` ~ `2` | 超范围会被夹到边界 |
| `max_tokens` | 默认 8192，上限 32768 | 超上限截断为 32768 |
| `tools` / `tool_choice` | OpenAI 标准格式 | 上游支持函数调用 |
